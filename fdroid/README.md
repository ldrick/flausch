# Releasing on F-Droid

F-Droid builds Flausch from source and signs it with its own key. Store texts, icon and screenshots come from
`fastlane/metadata/android/<locale>/`; `io.github.ldrick.flausch.yml` is the build recipe for
[fdroiddata](https://gitlab.com/fdroid/fdroiddata).

## A new version

1. Bump `version` in `Cargo.toml` and `version_code` in `[package.metadata.fdroid]`
   (`1 << 24 | major << 16 | minor << 8 | patch`, which cargo-apk uses; `cargo test` checks it).
2. Add `fastlane/metadata/android/{en-US,de-DE}/changelogs/<version_code>.txt` (max. 500 characters).
3. Commit, tag `v<version>` and push the tag. After the first release, F-Droid picks up new tags by itself
   (`UpdateCheckMode: Tags`).

## First submission

1. Fork fdroiddata on GitLab and copy `io.github.ldrick.flausch.yml` to `metadata/` there.
2. Optional, but catches most problems: `fdroid lint io.github.ldrick.flausch` and
   `fdroid build -v -l io.github.ldrick.flausch` in the fork (with fdroidserver, e.g. its Docker image).
3. Open a merge request with the "App inclusion" template.

## Notes

- cargo-apk always signs and has no unsigned mode, so the recipe signs with a throwaway key; F-Droid re-signs.
- Locally, `make apk-release` needs a keystore: set `CARGO_APK_RELEASE_KEYSTORE` and
  `CARGO_APK_RELEASE_KEYSTORE_PASSWORD`. Keep the keystore outside the repo.
- Screenshots: emulator (AVD "flausch") with the demo data and SystemUI demo mode; the store icon is generated by
  `tools/logo.py`.
