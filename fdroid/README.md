# Releasing on F-Droid

F-Droid builds Flausch from source and signs it with its own key. Store texts, icon and screenshots come from
`fastlane/metadata/android/<locale>/`; `io.github.ldrick.flausch.yml` is the build recipe for
[fdroiddata](https://gitlab.com/fdroid/fdroiddata).

## A new version

Releases go through a release PR (see "Workflow" in `AGENTS.md`):

1. Every push to `main` updates the release PR (Release workflow; the first release is 1.0.0). It bumps
   `version` and `version_code` (`1 << 24 | major << 16 | minor << 8 | patch`, which cargo-apk uses; `cargo test`
   checks it), updates this recipe and `CHANGELOG.md`, drafts
   `fastlane/metadata/android/{en-US,de-DE}/changelogs/<version_code>.txt` and opens the PR.
2. Edit the changelogs in the PR (max. 500 characters, German translated) and merge it.
3. The workflow tags `v<version>`. After the first release, F-Droid picks up new tags by itself
   (`UpdateCheckMode: Tags`).

## First submission

1. Fork fdroiddata on GitLab and copy `io.github.ldrick.flausch.yml` to `metadata/` there.
2. Optional, but catches most problems: `fdroid lint io.github.ldrick.flausch` and
   `fdroid build -v -l io.github.ldrick.flausch` in the fork (with fdroidserver, e.g. its Docker image).
3. Open a merge request with the "App inclusion" template.

## Notes

- F-Droid builds only arm64-v8a (`--target aarch64-linux-android`, about 9 MB instead of 18 MB with x86_64).
  Splitting per ABI would need a versionCode per ABI.
- Reproducible builds: F-Droid's APK equals the one the Release workflow attaches to the GitHub release, apart from
  the signature, so F-Droid can ship it with our signature (`Binaries` and `AllowedAPKSigningKeys` in the recipe).
  This needs the same pinned toolchain, SDK, NDK and `Cargo.lock`, and `--remap-path-prefix` for the build
  directory and `~/.cargo` in the recipe, the workflow and `make apk-release`. The JDK doesn't matter (Temurin and
  Debian's OpenJDK 21 give the same dex). Checked on 2026-11-18 with `fdroid build` in the fdroidserver buildserver
  image and fdroidserver's `verify_apks` against a local `make apk-release`.
- cargo-apk always signs and has no unsigned mode, so the recipe signs with a throwaway key. F-Droid strips that
  signature before comparing.
- The buildserver has no C compiler (build scripts need one), hence `build-essential` in `sudo`. NDK r28 stops at
  API 35, and cargo-apk then finds no usable platform for android-36, so the NDK is r30 or newer.
- Locally, `make apk-release` needs a keystore: set `CARGO_APK_RELEASE_KEYSTORE` and
  `CARGO_APK_RELEASE_KEYSTORE_PASSWORD`. Keep the keystore outside the repo.
- Screenshots: emulator (AVD "flausch") with the demo data and SystemUI demo mode; the store icon is generated by
  `tools/knit.py`.
